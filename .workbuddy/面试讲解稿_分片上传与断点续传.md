## 一、30 秒开场版（面试官问"讲一个你做过的功能"时的起手）

> 图片上传这个功能，我做的是**分片上传加断点续传**，核心解决两个问题：一是用户在弱网下传大图，一次请求挂了就要从头再传 20 MB，体验很差；二是上传过程可能持续很久，这段时间里的空间额度怎么管，才不会被并发开出来的多个上传会话绕过去。
>
> 方案是**上传会话**模型：图片上限 20 MB，超过 8 MB 走分片，片大小固定 5 MiB，最多 4 片。建会话时就把字节数额度**预留在途**，完成时结转为已用，取消和过期时释放。断点续传的事实放在服务端数据库，浏览器只存一个会话号做提示。分片先在浏览器算好哈希随片传过去，服务端流式接收时同步校验。最后由服`务端把分片拼成整图——数据不经过应用服务器——再走一遍和普通上传完全相同的校验、缩略图、落库流程。`

## 二、正文展开

### 2.1 为什么要分片（先给结论，再给数）

一次整体上传的失败代价是**全量重传**：20 MB 的图在移动网络下传到 18 MB 断掉，重传还是 20 MB。分片后断点粒度是 5 MiB，失败最多重传 1 片。同时整图 20 MB 一次请求对网关超时、请求体大小限制都不友好。

但小文件不值得分片：8 MB 以下分片最多 2 片，省下的流量（≤3 MB）抵不过固定开销——建会话一次往返、完成一次往返、每片一次哈希。所以设了 **8 MiB 分流阈值**：以下整体直传，以上分片。这是一个可以算出来的阈值，不是拍的。

### 2.2 上传会话模型（一条链路的骨架）

| 阶段      | 浏览器做什么             | 服务端做什么                                       |
| ------- | ------------------ | -------------------------------------------- |
| 建会话     | 带文件名、声明大小、片大小请求建会话 | 校验 ≤20 MB、片大小必须 5 MiB、**预留字节额度**，会话有效期 24 小时 |
| 逐片上传    | 切片、算每片哈希、逐片提交      | 校验片大小与哈希、落对象存储、记分片账                          |
| 断点续传    | 凭缓存会话号来问           | 返回会话状态 + 已传分片列表                              |
| 完成      | 请求完成               | 服务端拼装整图、校验、生成缩略图、落库、**额度结转**                 |
| 取消 / 过期 | 主动取消（或消失）          | 删临时分片对象、**释放预留**、会话关闭                        |

两份数据分工：**会话记录存"声明"**（总大小、总片数、过期时间、状态），**分片记录存"事实"**（片号、校验和、大小），且「会话 + 片号」建了唯一键——同一片并发传两次，数据库层面只会有一行，这是防重的最后防线。

### 2.3 额度两阶段：预留 → 结转（正确性核心）

**问题**：上传会话从创建到完成可能持续几小时。如果只在完成时校验额度，用户可以并发开 10 个会话，每个在建会话时都看到"空间够"，全部完成后空间被撑爆——而且每一行数据单独看都是对的，对账对不出来。

**方案**：空间表加一个「在途预留」维度，约束恒为：

> 已用字节 + 在途预留 + 本次声明 ≤ 上限

- **建会话**：条件更新把声明大小加进预留。影响 0 行即额度不足，立刻拒绝。这是条件更新，不是"先读再判断再写"——后者并发下每个请求都读到同一个旧值、同时通过校验。
- **完成**：一条更新语句同时做三件事——预留减掉声明、已用加上实际、图片件数加一，仍带上限条件作防御。失败会自动释放预留兜底。
- **取消 / 过期**：释放预留。

**预留为什么恒等于实际**：片大小锁死 5 MiB、总片数由声明大小算出、每片大小在提交时被逐一校验（非末片必须 5 MiB，末片 = 声明大小 − 前面所有片）。所以实际写入的字节不可能超过声明，预留不会少占。一旦允许片大小浮动，这套守恒就破了。

**件数维度**只在建会话时做快速失败（读的是可能过期的快照），真正的保证放在完成阶段的条件更新里——判断与扣减分离，判断只是让用户早点死心，扣减才是保证。

### 2.4 分片上传与校验（浏览器 + 服务端各算一遍）

浏览器侧：

- 切片是对文件对象的**引用视图**，不是内存拷贝——内存峰值恒等于单片 5 MiB，与文件总大小无关；
- 每片用浏览器原生加密接口算 SHA-256（原生实现，不是脚本逐字节循环），放请求头随片传；
- 串行逐片，最多 4 片不并行；每片成功就更新本地缓存，断点粒度 5 MiB。

服务端侧：

- 流式接收，边收边算同一个哈希，套一层 5 MiB 的读取上限（声明外流量直接掐断）；
- 两边哈希不一致 → 删掉这个分片对象、报校验失败；
- 同一片重复提交：大小一致且校验和一致 → 幂等返回当前进度，不重传；不一致 → 报冲突。

### 2.5 断点续传（"断点"到底存在哪）

**服务端数据库是唯一事实，浏览器只存一个会话号做提示。**

恢复流程三步：

1. 浏览器用「文件名 + 字节数 + 最后修改时间」三要素做指纹，从会话级本地存储里找缓存的会话号；
2. 拿会话号去服务端**查最新状态**——不信本地缓存，查到的是权威的已传分片列表；
3. 查到 → 跳过已传分片续传；查不到或会话已过期/结束 → 重建会话从零开始。

指纹撞车（同名同大小同时间但内容变了）不会造成脏数据——分片校验和会拦住报冲突。本地缓存只做"乐观命中"，正确性不依赖它。

**失败语义二分**（细节加分点）：

- 用户**主动取消** → 立刻调删除接口，服务端马上删分片对象、释放预留；
- **网络异常**等其他失败 → 不动会话，保留现场（分片还在、预留还占着），等恢复后续传。

取消要善后，中断要保现场——两种失败走两条路。

### 2.6 完成与拼装（数据不经过应用服务器）

完成请求时服务端校验分片齐全（片数对、片号连续），然后调对象存储的**服务端拼装能力**，把 N 个分片对象直接拼成一个整图对象——数据在存储内部流动，不过应用服务器，不占应用带宽和内存。

拼好的整图流式走一遍和普通上传**完全相同**的流程：临时文件 → 图片解码验证（防"扩展名是图片、内容不是"）+ 格式白名单 → 取宽高、生成缩略图 → 转存到正式路径（原图 + 缩略图两个对象）→ 落图片记录、建初始版本 → 额度结转。最后**无论成败都删掉全部临时分片对象**——临时对象的生命周期严格限定在会话内。

失败路径：任何一步抛异常，会话标记失败，已转存的正式对象补偿删除，预留由结转失败的兜底释放。

### 2.7 过期清理（预留不泄漏的最后一道保障）

会话有效期 24 小时。每小时一轮定时任务扫描过期但仍活跃的会话：删分片对象、释放预留、关闭会话。用户跑路了、浏览器关了、实例挂过又起来了，都靠这道兜底。用户感知的最坏预留释放延迟 ≈ 24 小时（过期）+ 1 小时（扫描间隔）= 25 小时。

## 四、追问预案（每条先给一句结论）

**Q1：为什么片大小固定 5 MiB，不让客户端自定义？**  
预留结算的守恒前提。片大小浮动的话，"实际写入 = 声明大小"不再恒成立，预留要么少占（漏洞）要么多占（泄漏），结算逻辑要复杂一整层。固定片大小是用一点灵活性换正确性。

**Q2：为什么不用对象存储原生的分片上传接口、浏览器预签名直传？**  
两个原因。一是安全边界：架构约束浏览器不直连对象存储，所有流量必须过后端做认证和权限控制。二是拼装后还有一串业务动作——图片解码校验、缩略图、落库、额度结转——原生拼装接口只给你一个拼好的对象，业务闭环还是要在后端做。自己管会话和分片账，反而让"断点事实在数据库"这个设计成立。

**Q3：为什么每片校验而不是整文件一个校验和？**  
整文件哈希在建会话时就得把全文件读一遍，慢；且片级校验让"哪片坏了重传哪片"成立，整文件校验失败等于全量重传。整文件校验和在模型里留了位置，当前实现里真正的防线是：片大小锁死 + 每片哈希 + 服务端解码验证是真图。

**Q4：两个请求并发传同一片会怎样？**  
功能上正确：分片表「会话 + 片号」唯一键兜底，只会有一行分片记录，不会出现脏数据。但并发撞唯一键时当前拿到的是服务器错误码而不是业务冲突码，这是一个可改进点——接住唯一键冲突转成幂等返回或冲突响应。

**Q5：为什么额度要两阶段，完成时一次性校验扣减不行吗？**  
会话存活数小时。一次性方案下，用户并发开多个会话，每个建会话时都通过校验，全部完成后超额——且每行数据单独看都对，对账对不出来。预留制让"已用 + 在途"任何时刻都不超上限，攻击窗口不存在。

**Q6：20 MB 就分片，是不是过度设计？**  
弱网下 20 MB 整体上传失败重传代价是全量 20 MB；分片后是 5 MB。且 8 MB 以下不分片——分片只在失败重传代价明确变大时启用，阈值是算出来的，不是拍的。如果产品上限提到 100 MB，这套模型不用改，片数上限到 10000 之前都够。

## 五、一图流（白板可用）

```
建会话 ──预留额度──► 逐片上传(哈希校验) ──► 完成：拼装→校验→缩略图→落库→结转
  │                     │                        │
  │ 断点：查会话拿已传片号，跳过已传              │ 删全部临时分片对象
  │                                              │
  └─ 取消/过期(24h+每小时扫) ──释放预留──► 会话关闭
```

额度恒等式（贯穿全程的一句话）：**已用 + 在途预留 + 本次声明 ≤ 上限，任何时刻成立。**
