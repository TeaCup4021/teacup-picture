# 视觉回归与产品图验收

产品图是目标设计，Playwright 截图是实现结果。两者不能混为同一个像素基线。

## 两层验收

1. 设计走查：实现页面与 `references/*.png` 比较布局、层级、颜色和交互，不要求逐像素相同。
2. 回归测试：页面完成走查后，用 Playwright 保存稳定截图，阻止后续无意变化。

当前 M1 页面已完成 UI v1.1 改造和人工截图走查，但正式 Playwright 像素基线尚未批准。M3 编辑器已完成 1440×900、1024×768、390×844 实现截图走查，正式像素基线仍待批准。M2 及 M4～M7 不得用产品图替代实现截图。

视觉命令默认直接退出，不启动开发服务器。页面完成设计走查后，在当前终端设置 `UI_VISUAL_BASELINE_APPROVED=v1.1`，再运行：

```bash
pnpm test:visual
pnpm test:visual:update
```

批准令牌只表示该次执行允许读取或更新基线，不应长期写入 `.env` 或 CI，除非相应页面已经正式启用视觉回归。

## 标准视口

- 桌面：1440 × 900。
- 紧凑桌面/平板：1024 × 768。
- 手机：390 × 844。
- 支持深色主题的页面额外覆盖深色桌面截图。

## 截图条件

- 固定时间、动画、随机数和图片资源。
- 等待字体、图片和请求完成。
- 禁用或减少动态效果。
- 使用稳定测试账号和可恢复测试数据。
- 不把 Cookie、密码、分享密码或敏感 URL 写入截图文件名和报告。

## 基线启用顺序

1. M1：公开图库、图片详情、个人空间、上传、管理员审核；人工走查已完成，像素基线待批准。
2. M2：AI 创建、AI 任务。
3. M3：编辑器已完成实现截图走查，稳定像素基线待批准。
4. M4–M5：团队空间、成员与协作。
5. M6–M7：分享、评论、通知和分析。

## 变更规则

- 视觉测试失败时先判断是缺陷还是已批准设计变化。
- 批量更新截图前必须在 PR 中附上差异说明。
- 已批准的设计变化需要同步更新页面规范、产品图或 `CHANGELOG.md`。
- 不得为了通过截图测试隐藏真实溢出、错误状态或未加载内容。
