# 通知、分享与评论

- 路由：`/notifications`，图片详情和链接分享页中的相关模块
- 里程碑：邀请通知 M4；分享、评论和批注 M6
- 状态：M6 分享、评论、批注和相关站内通知已实现；M4 邀请通知按对应里程碑维护
- 产品图：待补充

M6 互动以真实 `/api/v1` 数据和私有 MinIO 资源为准，不使用模拟讨论或本地分享状态。接口契约见 `../../m6-api-contract.md` 和 `../../openapi/m6.yaml`。

## 通知

- 顶部铃铛展示未读角标和最近通知，完整列表进入通知中心。
- 通知按邀请、评论、提及、批注和系统状态区分，并提供明确下一步。
- 已读状态不能只依赖颜色。
- M6 回复、提及、解决和重新打开复用既有 `notification` 表；邀请接受流程不因 M6 实现而被标记完成。

## 链接分享

- 支持有效期、访问密码、撤销和重新生成。
- 重新生成前明确提示旧链接立即失效。
- 分享链接和密码不得出现在日志、截图基线或分析事件中。
- 分享弹窗只在创建/重新生成后显示一次完整链接；再次打开只展示有效期和密码保护状态。
- `/shares/[publicId]` 先从 URL 片段读取密钥，通过请求体换取 Session 授权，再读取元数据和图片资源。
- 分享页提供校验骨架屏、缺少密钥、密码输入、无效/到期/撤销和资源加载失败状态。
- 未登录用户可以查看已授权分享；下载和讨论展示登录续办入口，登录成功返回含片段密钥的原路径。
- 页面 metadata 设置 `noindex`、`nofollow`、`no-referrer`，分享接口和资源使用 `no-store`。

## 评论与位置批注

- 普通评论和位置批注使用同一讨论语言，但位置批注必须显示锚点和解决状态。
- 回复、提及、已解决和重新打开产生清晰状态反馈。
- 未登录访客只查看已有公开评论；发表评论、下载和分享需要登录。
- 批注选点按图片内容盒归一化到 `[0,1]`，提交时携带当前 `pictureVersionId`。
- 提及使用成员选择器提交结构化用户 ID；候选仅来自图片所有者、团队成员和讨论参与者。
- 讨论按游标加载更多；删除后显示占位文案，不造成回复上下文断裂。
