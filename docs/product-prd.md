# 茶杯云图库产品需求与路线图

- 版本：v0.2
- 首次确认：2026-08-11
- 实现校准：2026-08-13
- 适用项目：`teacup-picture` 前后端 Monorepo，由现有 Spring Boot 后端向完整 AI 图片创作与协作平台演进

当前里程碑：M1 已完成，M2～M7 为规划。当前真实能力以代码、Flyway 和 `docs/openapi/m1.yaml` 为准；本文件中的后续里程碑不得被解释为已经实现。

## 1. 背景与目标

当前项目已经具备 Spring Boot 后端和 Next.js 前端，并完成 M1 的注册登录、默认个人空间、图片上传、公开申请、管理员审核、公开图库和详情闭环。遗留后端还包含空间、分析、AI 扩图和基础 WebSocket 代码，但未迁入 `/api/v1` 或未达到对应产品规则的能力不能视为前端可用。

后续目标是在 M1 基础上演进为 AI 图片创作与团队协作平台。用户最终应能够完成：

1. 上传已有图片或使用 AI 生成图片。
2. 对图片进行扩图和常用编辑。
3. 保存草稿、正式版本并恢复历史版本。
4. 创建团队空间，邀请成员共同编辑图片。
5. 实时查看其他成员的操作、光标和在线状态。
6. 将作品公开发布或通过受控链接分享。
7. 浏览公开图库，查看图片和评论。

项目同时作为互联网大厂前端岗位的工程实践项目，除功能可用外，还应体现 TypeScript、React/Next.js、状态管理、接口契约、性能优化、自动化测试、实时通信和工程规范等能力。

当前 M1 以 Chrome、Edge 最新两个主要版本为主要验收范围，同时适配 1440×900、1024×768 和 390×844。移动端提供完整的 M1 基础流程，但复杂编辑与协作仍以桌面端为主；Firefox 和 Safari 只保证基础可用。

## 2. 产品定位

茶杯云图库是一个面向个人与团队的 AI 图片创作和协作平台。平台以“图片资产 + 编辑版本 + 团队空间”为核心，连接图片上传、AI 绘图、AI 扩图、协同编辑、公开发布和受控分享。

平台主要解决以下问题：

- 用户能够集中管理上传图片和 AI 生成结果。
- 用户能够使用统一编辑器完成基础编辑、涂鸦、文字和图片调节。
- 团队成员能够在同一图片上实时协作。
- 图片编辑过程可追溯、可恢复，不因覆盖原图丢失历史。
- 作品能够经过审核进入公共图库，或通过链接定向分享。
- 评论和位置批注能够与具体图片版本建立关联。

典型用户旅程：

```text
上传已有图片 / AI 生成图片
  -> 个人编辑与 AI 扩图
  -> 创建团队并邀请成员
  -> 团队实时协作编辑
  -> 确认正式版本
  -> 提交公开审核或生成分享链接
  -> 其他用户查看、下载和评论
```

## 3. 用户与角色

### 3.1 平台角色

- 未登录访客：浏览公开图库、查看公开图片详情和评论；不能下载、评论、分享或编辑。
- 普通用户：注册登录、管理个人空间、上传图片、使用 AI、创建团队、加入团队、下载、评论和分享。
- 平台管理员：管理用户、图片审核、空间、公开内容和平台分析数据。

第一版只使用“平台账号 + 密码”注册登录，不加入短信验证码、微信、GitHub 等第三方登录，也暂不提供忘记密码、个人资料修改、头像上传和密码修改功能。

### 3.2 团队空间角色

后端现有团队角色继续沿用：

| 角色 | 权限 |
| --- | --- |
| `viewer` 浏览者 | 查看图片 |
| `editor` 编辑者 | 查看、上传、编辑、删除图片 |
| `admin` 管理员 | 编辑者全部权限，以及管理空间成员 |

团队空间还存在独立于角色的“所有者”概念：

- 每个团队空间只有一名所有者。
- 所有者是创建团队空间的用户，默认具备管理员权限。
- 一个团队可以有多名管理员。
- 所有权只能转让给现有管理员。
- 所有者在转让前不能退出团队。
- 团队必须始终保留至少一名管理员。

前端权限控制只用于导航、按钮和交互提示，最终权限必须由后端校验。

## 4. 核心概念

### 4.1 Picture

平台中的图片资产。图片至少包含原图、缩略图、名称、简介、分类、标签、尺寸、格式、主色调、创建者、所属空间和公开审核状态。

图片默认属于个人空间或团队空间。上传和 AI 生成不会自动公开，只有用户主动提交公开申请并审核通过后，图片才进入公共图库。

### 4.2 Personal Space

每名用户注册成功后自动创建一个默认个人空间，用于保存：

- 上传图片。
- AI 绘图和 AI 扩图结果。
- 编辑草稿。
- 正式版本和版本历史。
- 分享与评论关联数据。

默认个人空间私有可见，允许重命名但不能单独删除。用户只能删除其中内容或注销整个账号。

空间等级继续沿用后端配置：

| 等级 | 最大图片数 | 最大容量 |
| --- | ---: | ---: |
| 普通版 | 100 | 100 MB |
| 专业版 | 1,000 | 1 GB |
| 旗舰版 | 10,000 | 10 GB |

前端展示图片数量和存储容量的使用进度、接近上限提示和容量不足提示。第一版不建设支付和在线升级流程。

### 4.3 Team Space

围绕具体项目创建的多人协作空间。每名普通用户最多创建 5 个团队空间，可以加入多个其他用户创建的团队空间，加入的空间不计入创建上限。

每个团队空间拥有独立的：

- 所有者和成员列表。
- 角色权限。
- 图片、草稿和版本。
- 容量统计。
- 邀请和通知。
- 协作会话和操作记录。

团队空间删除后立即永久删除，不能恢复。删除前必须展示完整影响范围，要求所有者输入空间名称并重新验证当前账号密码。删除过程终止进行中的编辑和 AI 任务，并清理图片、COS 文件、版本、评论、分享、邀请、成员关系和协作数据。系统只保留不含图片内容的安全审计事件。

### 4.4 Draft / Picture Version

编辑历史分为两层：

- 操作历史：用于当前编辑会话的撤销和重做。
- 正式版本：用于长期保存、预览、对比和恢复。

编辑过程自动保存草稿，但不因每次移动或滑块调整创建正式版本。以下节点创建正式版本：

- 用户主动保存。
- AI 绘图完成。
- AI 扩图完成。
- 团队确认成果。
- 恢复历史版本。

每个版本记录创建者、创建时间、来源类型、版本说明和预览图。恢复旧版本时基于旧版本创建新的当前版本，不删除后续历史。

### 4.5 AI Task

AI 绘图和 AI 扩图统一抽象为异步任务。任务状态统一为：

```text
queued -> running -> succeeded
                  -> failed
                  -> cancelled
```

任务记录任务类型、模型、提示词、参考图、图片比例、清晰度、创建时间、状态、失败原因和生成结果。

### 4.6 Share

分享分为两类：

- 公开发布：图片通过审核后进入公共图库，可被发现和搜索引擎收录。
- 链接分享：图片不进入公共图库，通过不可预测的链接访问，默认禁止搜索引擎收录。

### 4.7 Comment / Annotation

评论支持普通讨论串和图片位置批注。位置批注使用归一化坐标保存，并绑定创建时的 `pictureVersionId`。切换到新版本后，旧版本批注仍可查看，但不会错误覆盖到新图上。

### 4.8 Invitation / Notification

团队邀请不再采用后端现有的“管理员直接添加成员”，而是使用待确认邀请：管理员搜索用户、指定角色、发出邀请，用户接受后才创建团队成员关系。

通知中心承载团队邀请、评论回复、提及、批注解决和重要系统状态。

## 5. Web 模式需求

### 5.1 用户账号

M1 当前能力：

- 用户可以通过平台账号和密码注册、登录、退出。
- 注册成功后自动创建默认个人空间。
- 登录成功后进入角色默认页：普通用户进入个人空间，平台管理员进入审核页。
- 未登录访问个人空间、上传或管理页面时展示权限状态和登录入口。

登录后返回原页面、个人资料、空间容量、AI 额度以及下载/评论/分享登录续办在对应后续里程碑实现。

当前后端使用 HttpSession 和 Sa-Token。前端使用 Cookie 会话，Axios 开启 `withCredentials`，不在 `localStorage` 保存 Token。

### 5.2 公开图库

公开图库作为网站首页，不制作独立营销落地页。

M1 当前能力：

- 只展示审核通过且仍处于公开状态的图片。
- 使用瀑布流布局，强调图片展示和内容发现。
- 一次读取公开接口返回的当前批次，展示图片、标题、作者和发布时间。
- 未登录用户可以查看公开图片详情。
- 提供 loading、empty 和 error 状态。

游标续页、无限滚动、返回位置恢复、搜索、筛选和热度排序尚未实现。热度指标必须由后端提供并按访客标识、用户和时间窗口去重；没有真实接口前不展示浏览量或点赞量。下载、评论、分享和团队编辑属于 M4～M6。

### 5.3 图片上传与管理

普通用户上传页只开放：

- 本地图片上传。
- 图片 URL 上传。

不向普通用户开放后端现有的 Bing 关键词批量抓图接口，也不使用 `FileController` 中的测试上传接口。

上传规则：

- M1 只上传到当前用户的默认个人空间。
- 单张图片最大 20 MB。
- 支持 JPEG、JPG、PNG、WebP。
- 第一版只显示统一加载状态和最终成功/失败结果。
- 暂不提供精确上传进度、取消和自动重试。

M1 个人空间使用规则网格和客户端状态筛选，暂未接入服务端分页、URL 查询状态或批量操作。团队目标空间、分页和批量元数据修改在 M4 契约确认后实现。

### 5.4 AI 绘图与 AI 扩图

AI 绘图输入：

- 模型。
- 图片比例。
- 图片清晰度。
- 可选参考图片。
- 提示词。

AI 扩图输入：

- 待扩图图片。
- 模型。
- 图片比例。
- 图片清晰度。
- 可选参考图片。
- 提示词。

任务过程中展示加载动画和任务状态。生成完成后：

- 结果自动保存到用户个人空间。
- 用户可以下载到自己的电脑。
- 用户可以继续编辑、加入团队或提交公开审核。
- AI 扩图可以将结果设置为当前版本，但必须保留原图版本。

模型列表由后端配置并返回，前端不硬编码模型名称。管理员能够配置模型名称、支持能力、比例、清晰度、启用状态和配额规则。具体模型供应商在实现阶段确定。

普通用户每日拥有两个独立配额：

```text
AI 绘图：100 次/日
AI 扩图：100 次/日
```

额度按日重置。平台或模型服务失败时自动返还；用户主动取消是否返还，根据任务是否已产生实际调用成本判断。

AI 任务中心保留完整历史，展示提示词、模型、参考图、参数、状态、结果和失败原因。

### 5.5 图片编辑器

第一版编辑器需求：

基础变换：

- 旋转。
- 裁切。
- 缩放。

涂鸦图层：

- 自定义颜色。
- 笔刷粗细。
- 笔刷种类。
- 擦除。

文字图层：

- 文字内容。
- 字体大小。
- 颜色。
- 位置拖动。
- 删除文字。

图片调节：

- 曝光、亮度、对比度、高光、阴影。
- 饱和度、自然饱和度、色温、色调。
- 锐度、褪色、暗角、增强、去雾。

编辑数据需要采用结构化操作或图层模型，不能只保存最终像素。底层编辑器组件暂不锁定，Fabric.js、Konva、自研 Canvas 和其他成熟组件在实现阶段对比后决定。

### 5.6 团队、成员和邀请

用户可以创建多个团队空间，普通用户最多创建 5 个。

成员邀请流程：

```text
管理员通过平台账号精确搜索或昵称模糊搜索用户
  -> 选择 viewer 或 editor
  -> 创建 pending 邀请
  -> 被邀请用户收到站内通知
  -> 用户接受后创建成员关系
  -> 用户拒绝或邀请过期则不加入团队
```

搜索结果展示头像、昵称和部分脱敏账号。已加入或已有待处理邀请的用户不能重复邀请。新增管理员通过成员加入后的角色提升完成。

顶部导航通知铃铛展示未读角标和最近通知，并可进入完整通知中心。第一版不接短信和邮件。

### 5.7 多人实时协作

目标是所有协作者实时看到其他成员的编辑操作、光标和在线状态。

协作原则：

```text
每张图片的当前版本对应一个协作房间
进入房间获取当前快照、版本号和在线成员
操作携带唯一操作 ID、对象 ID 和基础版本号
服务端校验权限并分配全局操作顺序
客户端按服务端顺序应用操作
断线重连后获取遗漏操作或最新快照
光标和在线状态使用临时消息，不写入正式版本
```

不同对象允许并行编辑；多人修改同一文字、涂鸦对象或全局调节参数时，采用对象级软锁和冲突提示。CRDT、OT 或具体协作库留到实现阶段比较。

当前后端只支持单人编辑、多人旁观，并且只广播放大、缩小和旋转操作，需要扩展为真正的多人实时协作协议。

### 5.8 分享与评论

公开发布规则：

- 审核通过后进入公共图库。
- 未登录用户可以查看。
- 登录用户可以下载和评论。
- 受邀 `editor` 或 `admin` 可以继续编辑。
- 图片所有者可以申请撤回公开状态。
- 平台管理员可以撤下违规图片。

链接分享规则：

- 默认有效期 7 天。
- 支持 1 天、7 天、30 天、自定义时间或永久有效。
- 支持访问密码。
- 所有者可以随时撤销或重新生成链接。
- 重新生成后旧链接立即失效。
- 链接图片不进入公共图库并设置 `noindex`。

链接访问权限：

```text
未登录：通过有效链接查看图片
已登录：查看、下载、评论
受邀 editor/admin：继续编辑
```

评论需求：

- 发表评论和回复评论。
- 删除自己的评论。
- 图片所有者和团队管理员管理评论。
- 在图片具体位置添加批注。
- 评论和位置批注形成讨论串。
- 讨论串可以标记为已解决或重新打开。
- 回复、提及和解决状态产生站内通知。

### 5.9 公开审核与管理后台

公开审核流程：

```text
私人图片
  -> 用户提交公开申请
  -> pending 待审核
  -> approved 审核通过，进入公共图库
  -> rejected 审核拒绝，保持私有并返回原因
```

M1 管理员审核页当前支持：

- 待审核列表。
- 原图、作者和图片元数据预览。
- 通过或拒绝。
- 填写拒绝原因。

审核记录、撤回已发布图片、批量审核和用户举报尚未实现；其中审核记录和撤回已有后端契约，前端需在后续管理能力完善时接入。

管理后台还包含用户管理、空间管理、内容与评论管理。普通管理员权限与团队空间管理员权限必须分开。

### 5.10 空间数据分析

复用后端现有能力展示：

- 空间使用量。
- 图片分类分布。
- 图片大小分布。
- 成员上传行为。
- 空间使用排名。

查看权限：

- 个人空间分析仅空间所有者可见。
- 团队空间完整分析仅所有者和管理员可见。
- 平台空间排名仅平台管理员可见。

## 6. 技术架构

### 6.1 前端技术栈

最终选定：

```text
React + TypeScript + Next.js App Router
Ant Design
TanStack Query
Zustand
Axios
React Hook Form + Zod
ECharts
WebSocket
Vitest + React Testing Library
Playwright
ESLint + Prettier
pnpm + Node.js 20 LTS
```

因公开图库和图片详情需要搜索引擎收录，应用框架由最初讨论的 React + Vite 调整为 React + Next.js。Vite 不再作为应用构建工具，Vitest 仍用于单元测试。

### 6.2 渲染与 SEO

目标采用混合渲染：

- 公开图库、公开图片详情：目标为 SSR/ISR；当前 M1 页面骨架静态生成，业务数据在客户端读取，尚未完成 SEO 数据渲染和缓存失效。
- 登录后的个人空间、团队空间、AI 任务、通知和管理后台：客户端请求。
- 图片编辑器：纯客户端加载，不参与 SSR。

允许搜索引擎收录：

- 公开图库。
- 审核通过的公开图片详情。
- 后续公开作者页。

禁止收录：

- 个人空间、团队空间。
- AI 任务和图片编辑器。
- 管理后台和通知中心。
- 仅链接分享的图片。
- 登录和注册页。

ISR 及后端事件触发的缓存失效尚未实现。实现前，私有页面和管理页面禁止使用公共缓存，并需补齐 `noindex` 验证。

### 6.3 前端分层与状态管理

目录按业务领域组织：

```text
src/
  app/          路由、布局、页面入口和 Provider（Next.js App Router）
  widgets/      页面级组合模块
  features/     登录、上传、评论、分享、AI、协作等功能
  entities/     User、Picture、Space、Comment 等领域模型
  shared/       通用组件、工具、请求层、样式
  api/
    generated/  OpenAPI 自动生成代码
```

具体目录需要遵守 Next.js App Router 约束，实现阶段可调整命名，但业务模块边界不能取消。

状态分层：

```text
TanStack Query：用户、图片、空间、评论、通知、AI 任务等服务端数据
Zustand：当前空间、主题、编辑器 UI、临时全局交互状态
React state：表单、弹窗和局部选择状态
```

接口列表不能复制进 Zustand，服务端数据更新通过 Query invalidation 处理。

### 6.4 API 契约

以后端 OpenAPI 为接口唯一事实来源：

```text
Spring Boot DTO / OpenAPI
  -> 自动生成 TypeScript 类型
  -> 前端业务 API 封装
  -> TanStack Query Hooks
  -> 页面与组件
```

页面不能直接调用生成代码或拼接 URL。Java `Long` 在前端统一按 `string` 处理，避免 JavaScript 大整数精度丢失。M1 使用 `openapi-typescript` 生成类型；后续契约沿用同一流程，除非另有架构决策。

接口统一迁移到 `/api/v1`，资源名称使用小写复数和短横线。保留统一响应结构，并增加正确的 HTTP 状态码和 `requestId`：

```json
{
  "code": 0,
  "data": {},
  "message": "ok",
  "requestId": "req_xxx"
}
```

公开只读 API、登录业务 API 和管理员 API 分开：

```text
/api/v1/public/**  匿名可读，仅返回审核通过的公开数据
/api/v1/**         登录用户业务接口
/api/v1/admin/**   平台管理员接口
```

### 6.5 图片资源

- 公开图库和图片详情使用 Next.js Image 与缩略图。
- 管理页面优先加载缩略图，详情操作时加载原图。
- 编辑器使用已配置 CORS 的原始图片 URL。
- COS 必须允许目标前端域名和必要响应头，否则 Canvas 导出会失败。

### 6.6 性能目标

- 图片列表懒加载和失败占位。
- 公开图库虚拟化或分批渲染。
- 管理空间批量选择不加载全部原图。
- 搜索输入防抖。
- 大型编辑模块路由懒加载。
- WebSocket 光标和高频操作消息节流。
- 从公开详情返回时恢复滚动位置（当前未实现）。

### 6.7 测试与可观测性

Vitest 覆盖 API 适配、权限判断、状态逻辑和编辑器核心工具函数。React Testing Library 覆盖登录表单、上传、评论和权限按钮。Playwright 覆盖：

- 注册与登录。
- 图片上传。
- AI 任务提交和结果进入个人空间。
- 团队邀请与接受。
- 图片评论和分享。
- 管理员审核。

错误处理要求：

- Axios 统一解析响应和错误。
- 页面级 Error Boundary。
- 前后端通过 `requestId` 联合排查。
- 记录 WebSocket 连接、重连和异常。
- 记录 AI 任务状态和失败原因。
- 生产环境接入前端错误监控，具体工具后续确定。
- 日志不得记录密码、Cookie、分享密码和敏感 URL。

## 8. 环境配置

前端环境分为：

```text

test
production
```

建议前端变量：

```bash
NEXT_PUBLIC_API_BASE_URL=http://localhost:8123/api/v1
NEXT_PUBLIC_WS_BASE_URL=ws://localhost:8123
NEXT_PUBLIC_ASSET_BASE_URL=https://example-cos-host
```

所有 `NEXT_PUBLIC_` 变量都会暴露给浏览器，不得存放 COS 密钥、模型密钥、会话密钥或服务端 Token。服务端私有环境变量不得使用 `NEXT_PUBLIC_` 前缀。

本地开发已使用 Docker Compose 管理 MySQL 和 Redis，后端与前端仍在宿主机运行。Nginx、应用容器化、CI/CD 和正式生产部署在部署阶段再讨论；以 `docker/README.md` 为当前本地运行说明。

后端数据库引入 Flyway 管理版本。开发、测试和 Docker 环境执行同一套迁移脚本，禁止只修改本地数据库而不提交迁移。

## 11. 视觉与交互规范

整体视觉参考飞书的协作效率和 X 的内容发现体验，不直接复制品牌界面。

- 默认使用明亮、克制的中性色背景，蓝色作为主交互色。
- 公开图库突出图片和连续浏览。
- 个人空间、团队空间使用紧凑侧边导航和规则网格。
- 编辑器采用深色工作区，减少画布周围干扰。
- 通知、在线成员、头像和协作状态保持紧凑清晰。
- 减少装饰性渐变和无意义动画。
- 使用 Ant Design 基础组件，自定义图片卡片、瀑布流、编辑器和协作界面。

主题：

- 当前 M1 只提供浅色主题，并使用 CSS 变量和 Ant Design Theme 统一视觉。
- 全站深色主题及用户偏好保存尚未排入已启动里程碑；实现前不得在组件内零散硬编码第二套主题。

语言与无障碍：

- 第一版只提供简体中文。
- 日期、数字和文件大小按中文习惯格式化。
- 支持键盘操作、清晰焦点、表单标签和足够颜色对比度。
- 状态不能只依赖颜色表达。

M1 已从原型阶段进入真实 API 实现。后续页面可先制作隔离的产品图或交互原型，但不得把模拟数据接入正式业务路由，也不得用原型状态替代后端缺口。

## 12. 关键风险与待决策项

### 12.1 当前后端缺口

M1 `/api/v1` 闭环已经实现。团队空间事务、AI 任务、版本、评论、分享、通知、邀请、协作持久化、可靠热度统计和公网安全加固仍未完成。具体代码事实、优先级和验收标准只在 `docs/backend-gap-analysis.md` 维护，避免本 PRD 复制一份过期清单。

### 12.2 暂缓技术决策

- 公开图库搜索范围、筛选项和热度算法。
- 编辑器底层组件。
- CRDT、OT 或其他协同实现。
- AI 模型供应商和模型组件。
- 应用容器化、Nginx 和生产网络方案；本地 MySQL/Redis Compose 已确定。
- 正式生产部署与 CI/CD。

### 12.3 安全上线边界

安全问题的当前完成状态和公网部署阻断项只在 `docs/backend-gap-analysis.md` 维护，避免在 PRD 中复制后过期。原则上密码哈希、CSRF、限流、SSRF、上传内容校验、WebSocket Origin、COS 和分享访问控制必须在对应能力公网开放前通过专项验收。本地 Docker 可运行不等于已满足公网安全要求。

## 14. 当前结论

```text
AI 图片创作
  + 可恢复的结构化编辑
```
